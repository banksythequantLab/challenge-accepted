Make the docs describe what exists, and survive a Cloud Run restart

Checked the actual Devpost rules: deadline Aug 31 5pm PDT, README must carry a
step-by-step spin-up guide, private repos must grant access to testing@devpost.com
and cloudhackathons@google.com. The docs were failing the first of those and
actively misrepresenting the build.

README said "v0.1", "10 tests", and "Not built: Cloud Run deploy" -- for a project
that is deployed, Firestore-backed and driven end to end from the browser. It is
the first thing a judge reads and it was selling the project short by two months
of work. Rewritten: real status, live URLs, local run, the four browser-driven
verification scripts, and a deploy section including the IAM grants deploy.ps1
does NOT perform (checked the script rather than trusting memory -- the roles were
granted by hand and would have stranded anyone else on the first build).

The architecture diagram drew Memory Bank, Agent Engine Sessions and a persistent
Agent Engine sandbox as if all three were live. None are. Those cards are now
dashed and labelled NOT WIRED -- PLANNED, with a legend for the convention, and
the code-execution card names the BuiltInCodeExecutor actually in use. The client
band claimed Next.js on Cloud Run with Firebase Auth and React Flow; it is one
static HTML file with anonymous localStorage ids, and now says so. The Firestore
edge claimed real-time listeners; it is a 4-second poll of /api/*.

Sessions live in server memory until an Agent Engine exists, so a Cloud Run
restart leaves the browser holding a sessionId the server has never heard of --
and judging runs for seven weeks, during which instances certainly recycle. Every
send after that failed silently with no hint that reloading would fix it. startRun()
now rebuilds a dead session and retries once.

scripts/check_session_recovery.py proves it the only way worth trusting: it DELETEs
the session out from under a live page, asserts the server really 404s it, then
requires the next turn to still get an answer. It does.

Demo script updated for the app as it now exists -- there is no sign-in, so the
two-user beat needs incognito rather than "signed in as different users" -- plus a
copy-to-Claude beat, /api/healthz for the required proof-of-deployment shot, and
two explicit warnings: do not say "Memory Bank" on camera, and do not read out
challengeaccepted.app until it actually resolves.

52 tests pass; copy and session-recovery checks pass.
